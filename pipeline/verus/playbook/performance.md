Replace output::retain's linear insertion-position search with a verified binary search over the sorted candidate prefix. When the prefix already has 100 candidates and the new candidate does not outrank its last row, return immediately without searching, inserting, or popping. Preserve exact descending-count/ascending-byte-name ordering. Only crate/src/output.rs changes; auxiliary state, inputs, glue, maintenance, and trusted base remain unchanged. This reduces candidate comparisons from up to 100 to at most about 7, or one for rejected full-prefix candidates, without adding SF1-specific state or copying snapshot state. Considered auxiliary-state restructuring, but retained the existing shared indexes. Direct changes to GetRowPointers and other DuckDB engine hotspots are infeasible here because engine sources are not in the permitted workspace and glue is frozen; this does not rule out future input restructuring. ## Reject noncompetitive top-100 candidates using the current tail

In output::select, once the selected Vec has 100 rows, compare the incoming candidate with selected[99] using the full count-descending/name-ascending comparator. If it cannot beat the tail, skip retain's linear insertion scan, insertion and pop. Prove this from the sorted prefix and strict-order transitivity with lemma_reject_tail; retain the existing checked multiplication and output range checks. This uses O(100) temporary state, adds no auxiliary state or maintenance work, and remains useful for larger parameter slices at SF3000. Considered a persistent ranked-group structure but did not adopt it: the simple cutoff avoids additional write maintenance and ranking invariants. No maintenance optimization was attempted; lower sampled write overhead must not be attributed to this read-only patch.

## Early-reject full top-100 candidates in output::select

For TPC-H Q21's read path, `output::select` scans positive name groups and maintains the best 100 in sorted order. Once the buffer is full, the old `retain` path always ran its linear insertion scan and Vec insert/pop even when the candidate was worse than the current 100th row. Add a one-comparison guard in `select`: if `selected.len() == 100` and the candidate is not better than `selected[99]`, prove the existing top-100 sequence is unchanged and continue. This is SF-size independent: it preserves a full scan of the queried nation's groups and only removes work for rows that cannot enter the LIMIT 100 result. Keep the proof with `lemma_sorted_limit` and `lemma_insert_after_last`; no structural or trusted-base change.

_Evidence (tpch q21):_ Measured on SF1 with Verus store and write mixes 0.01,0.05. Same-run pre-change benchmark score 48.070539 (read speedup 77.0884); post-change score 50.478554 (read speedup 82.7908), +5.01% versus the measured baseline and above the stated 0.4% run noise. `verus_verify`: 205 verified / 0 errors, trusted-base clean. Frozen `verus_test` with proofs and concurrent snapshots: 22 differential transactions, 120 checks, 0 mismatches; 200 snapshot writes, 1147 checks, 0 mismatches, 0 reader failures. Post-change steady-state profile: `output::select` share 0.1121 versus 0.136 before; kernel read share 0.1581 versus 0.192 before.

## Singleton group fast path improves Q21 read score

The SF1 qualifying parameter slices used by the benchmark produce one group, while production slices can be much larger. Added `Index::only` to recognize a root leaf and a verified singleton fast path in `output::select`, preserving the full cursor/top-100 scan for all larger slices. Also gave the bounded selection/output vectors capacity hints. This is read-only state traversal, does not change maintenance, and keeps state/read costs scale-safe because the fast path is O(1) only when the slice is already a singleton.

_Evidence (tpch q21):_ verus_verify: 206 verified, 0 errors, trusted base unchanged. verus_test with proofs and concurrent snapshots: 120 differential checks and 1147 snapshot checks, 0 mismatches; Verus store. verus_bench SF1 with write mixes 0.05,0.01: score 53.8361 versus prior best 48.645, +10.7% and well above 2.7% noise; read_speedup 84.2333, write-mix speedups 7.2476 and 27.2581.
