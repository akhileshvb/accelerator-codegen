## Choose the shorter exact-date probe or sparse-support scan without maintaining prefixes

For a nation-keyed daily count/revenue profile with arbitrary independent DATE bounds, widen endpoints before computing W=max(0,end-start). For each selected nation with D occupied days, enumerate and hash-probe the half-open day interval only when W<=D; otherwise scan that nation's sparse support and filter dates. This shortcut is a design choice, not a measured speedup.

## Size-derived overlay budgets should count incoming work before cancellation

For an Arc base plus sorted additive delta runs, budget compaction against cumulative incoming run-size credit, not just currently retained overlay entries. Coalescing repeated-key corrections can keep physical overlay support small while update history/level credits grow. Round each nonempty transaction run to power-of-two size credit, carry credit through equal-level merges, and reset cumulative credit only at base consolidation. A threshold proportional to base support bounds the number of overlay levels independently of total lifetime writes. Admit consolidation's aggregate-support latency spike; this is an amortized collection-based design, not a proof of worst-case touched-key-only persistence.

_Evidence (tpch q6):_ Q6 analysis revision, October 3, 2026: inputs accepted again by verus_check_inputs with one unfiltered four-column scan, one lossless lineitem delta and no rescans. The spec's weighted product permits price-only changes with delta_count=0 and delta_revenue!=0. Analytic counterexample: repeated corrections at one key occupy at most one cell per tier even as cumulative incoming update count grows; retained P can be O(log U) while U grows without bound, so a P>=base_support trigger need not bound lifetime history. Revised analysis budgets U>=max(1,base_support), retains both count and revenue weights, and states O(base_support+U) consolidation worst cases. No runtime benchmark or kernel proof was performed.

## Temporal profiles need count support and a pre-join maximum

For independent date intervals, persist sparse bounded daily count/revenue prefixes rather than raw facts or final winners. Retain a day or group when its count is positive, even if its revenue is zero or negative. Compute the maximum across every fact group before probing dimension bags: an orphan maximum must suppress joined runners-up. Exact projected supplier multiplicities preserve duplicate rows and byte-sensitive payloads. Fixed-depth Arc/Vec radix pages can replace only touched paths and physically remove empty branches, avoiding whole-map snapshot copies and unbounded overlays. Use a last-prefix fast path for fully covered blocks and a loop-based merge sort for tied keys; do not claim large-scale speed or memory fit from these correctness tests.
