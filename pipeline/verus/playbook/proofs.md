## Declare fresh runtime row types, including delta OF types

In q.inputs, avoid reusing a frozen spec row type as either a scan AS type or a lossless delta OF type. Use distinct runtime names such as SupplierScan and SupplierInput; the generated view functions still project them to the spec SupplierRow. Acceptance of the input declarations is not verification of the kernel.

## Persistent ordered indexes: intrinsic validity, cursor entry-state links, and narrow unfolding

Keep an ordered index's executable root private, expose its representation through a closed spec accessor, and attach ordering validity to the index type. Invoke use_type_invariant in executable accessors; export separate proof-only model lemmas with an explicit wf premise, because a spec-mode reference in a proof function does not by itself authorize use_type_invariant. For an inorder cursor, carry both remaining entries and a nonnegative work measure: 2*current.size plus the stack sum of 1+2*right_subtree.size. Descent and popping each reduce this measure by one. Besides preserving the ghost initial remaining sequence and work, explicitly relate those ghost values to old(self) in loop invariants; local assertions can succeed while mutable postconditions still fail without that entry-state link. Prove rotations by preserving the concatenated inorder entries, then transfer ordering and lookup semantics using local lemmas. Prefer explicit one-node decompositions to globally increasing recursive entries fuel; hiding unrelated wf/lookup definitions keeps the rotation VC small. These are foundational proofs, not a completed query proof.

_Evidence (tpch q21):_ Baseline verus_verify: 97 verified / 30 failing checks, 2.6 s, trusted-base clean. Intrinsic Index validity plus private-root/closed-accessor changes: 116 / 10, 2.5 s. Adding explicit old(self) cursor links changed 118 / 9 at 2.7 s to 119 / 8 at 2.5 s. A balance proof with global entries fuel 4 hit the resource limit (130 / 5, 4.7 s); removing that broad unfolding and asserting per-child decompositions verified rotations (131 / 4, 3.6 s). Latest check verifies the entire index module, checked scalar count updates, SQL count factorization, and the missing-nation result lemmas: 152 verified / 3 failing checks, 4.1 s; trusted-base clean. Remaining failures are build/apply State construction and nonempty query output.

## Q21: exact neighborhood maintenance and weighted-index delta joins

Prove the top-level state meaning through exact named lookup predicates (W, supplier/nation bags, buckets, name references). For EXISTS/NOT EXISTS maintenance, reconstruct touched pre-neighborhoods from post rescans minus signed captures; split the waiting sum into touched contributions and an unchanged outside part. For bucket maintenance, carry processed-prefix sums through both delta loops, then use a common ghost sort/deduplicated key universe to turn indexed weighted folds into lookup sums. The pointwise identity is B_new = B_old + delta_W*S_old + W_new*delta_S; it handles bag duplicates and sparse zero/absent lookups without FK or uniqueness assumptions. Name the higher-order product closure (weighted_entry) and explicitly use sum_ext_all to bridge mapped runtime rows to weighted_index: logically equal captured lambdas did not normalize automatically. Unfold count/lookup equalities before nonlinear arithmetic, and give the isolated scalar identity explicit requires. Alternative quantifier triggers for total/late lookups worked where a multi-pattern required both terms. In high-level scan/update proofs, hide recursive Tree::at/entries/wf to avoid solver expansion. A bounded sorted-vector top-100 implementation makes the query-result proof an insertion/prefix theorem with an exhibited full sorted ghost sequence.
