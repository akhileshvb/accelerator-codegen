## Declare fresh runtime row types, including delta OF types

In q.inputs, avoid reusing a frozen spec row type as either a scan AS type or a lossless delta OF type. Use distinct runtime names such as SupplierScan and SupplierInput; the generated view functions still project them to the spec SupplierRow. Acceptance of the input declarations is not verification of the kernel.

## Persistent ordered indexes: intrinsic validity, cursor entry-state links, and narrow unfolding

Keep an ordered index's executable root private, expose its representation through a closed spec accessor, and attach ordering validity to the index type. Invoke use_type_invariant in executable accessors; export separate proof-only model lemmas with an explicit wf premise, because a spec-mode reference in a proof function does not by itself authorize use_type_invariant. For an inorder cursor, carry both remaining entries and a nonnegative work measure: 2*current.size plus the stack sum of 1+2*right_subtree.size. Descent and popping each reduce this measure by one. Besides preserving the ghost initial remaining sequence and work, explicitly relate those ghost values to old(self) in loop invariants; local assertions can succeed while mutable postconditions still fail without that entry-state link. Prove rotations by preserving the concatenated inorder entries, then transfer ordering and lookup semantics using local lemmas. Prefer explicit one-node decompositions to globally increasing recursive entries fuel; hiding unrelated wf/lookup definitions keeps the rotation VC small. These are foundational proofs, not a completed query proof.

_Evidence (tpch q21):_ Baseline verus_verify: 97 verified / 30 failing checks, 2.6 s, trusted-base clean. Intrinsic Index validity plus private-root/closed-accessor changes: 116 / 10, 2.5 s. Adding explicit old(self) cursor links changed 118 / 9 at 2.7 s to 119 / 8 at 2.5 s. A balance proof with global entries fuel 4 hit the resource limit (130 / 5, 4.7 s); removing that broad unfolding and asserting per-child decompositions verified rotations (131 / 4, 3.6 s). Latest check verifies the entire index module, checked scalar count updates, SQL count factorization, and the missing-nation result lemmas: 152 verified / 3 failing checks, 4.1 s; trusted-base clean. Remaining failures are build/apply State construction and nonempty query output.

## Q21: exact neighborhood maintenance and weighted-index delta joins

Prove the top-level state meaning through exact named lookup predicates (W, supplier/nation bags, buckets, name references). For EXISTS/NOT EXISTS maintenance, reconstruct touched pre-neighborhoods from post rescans minus signed captures; split the waiting sum into touched contributions and an unchanged outside part. For bucket maintenance, carry processed-prefix sums through both delta loops, then use a common ghost sort/deduplicated key universe to turn indexed weighted folds into lookup sums. The pointwise identity is B_new = B_old + delta_W*S_old + W_new*delta_S; it handles bag duplicates and sparse zero/absent lookups without FK or uniqueness assumptions. Name the higher-order product closure (weighted_entry) and explicitly use sum_ext_all to bridge mapped runtime rows to weighted_index: logically equal captured lambdas did not normalize automatically. Unfold count/lookup equalities before nonlinear arithmetic, and give the isolated scalar identity explicit requires. Alternative quantifier triggers for total/late lookups worked where a multi-pattern required both terms. In high-level scan/update proofs, hide recursive Tree::at/entries/wf to avoid solver expansion. A bounded sorted-vector top-100 implementation makes the query-result proof an insertion/prefix theorem with an exhibited full sorted ghost sequence.

## Differential comparisons must honor SQL ordering ties

For an ORDER BY without complete tie breakers, compare SQL-permitted orderings rather than exact row sequences inside tied runs. A deterministic kernel refinement can satisfy the frozen query_result specification while an engine's concurrent or hash-dependent tie order differs. Do not change a verified/spec-permitted comparator to chase nondeterministic engine order or edit frozen fixtures; report the harness mismatch with the tied ORDER BY values.

## Code-first compatibility: map mutation and mutable post-state syntax

Use std::collections::HashMap with vstd's standard-library specifications, not the private HashMap import in vstd::hash_map. In this toolchain HashMap::get_mut is unsupported: remove an owned entry, update it, then reinsert it; this also makes the map's intermediate and final ghost views explicit. Verus rejects mut self receivers: move self into a mutable local instead. Mutable-reference postconditions require final(self) for post-state dereferences and old(self) for pre-state. For input scan loops, a loop-local let ghost processed = index as int avoids exec-mode casts during assignments to a ghost index; use the executable index cast directly in prefix-sum invariants.

_Evidence (tpch q18):_ Q18 code-first verus_test(proofs=false) surfaced each limitation before runtime. After replacing get_mut at four sites and adding final(self) to eight helper contracts, the kernel compiled and executed 40 ApplyDelta transactions and 276 queries with zero bag mismatches, write errors, or fallbacks. Proof verification has not been attempted; the order-only differential gate remains unresolved.

## Diagnose ORDER BY ties with a SQL-fallback control before changing a kernel

When a frozen query orders by only part of its GROUP BY key, validate the result bag plus monotonicity of the declared ORDER BY columns, not exact row-by-row equality inside tie runs. A kernel may choose deterministic extra tie breakers, but matching the engine's unspecified tie order is not part of query correctness. An execute=None control can identify a differential ordering-check issue even when both answers come from SQL. Do not change frozen query/spec/tests or overfit a comparator to incidental engine tie order; record the checker issue and distinguish bag correctness from an overall green test gate. snapshots=true may not reach the concurrent-reader phase when differential checks fail first.

## Code-first kernels still need ghost-mode and mutable-reference compatibility

For executable-only Verus bring-up, use std::collections::HashMap (vstd::hash_map::HashMap is a private import in this toolchain). Carry a processed-prefix index as a Ghost<int> wrapper and update it with Ghost(index as int), avoiding proof blocks solely for ghost bookkeeping. ## Check decimal fallback values before using fallback to handle SQL ties

A kernel may safely return None at its proof boundary, but the host's SQL fallback must preserve decimal values and scales. Before using fallback for engine-specific tie-order compatibility, test the host-visible result. If fallback changes values, remove the workaround rather than compensating with fixture-specific arithmetic or changing a sound kernel result. A fixed executable comparator also cannot track the engine's varying order of fully tied rows; repair tie-aware differential comparison or the host fallback path.

## Q13 bag histogram proofs: finite-support universes and named join weights

State C and Q as database indicator sums and H as a sum over deduplicated customer keys, with one contribution when C>0 and C*Q equals the bucket. For build, carry processed-prefix sums and explicitly equate the full take with the original sequence at loop exit. For apply, first coalesce both tables, transfer capture equations to C/Q, then use a deduplicated union of old customer keys, new customer keys and touched keys to prove H_after-H_before equals the sum of touched contribution differences. A general distinct-support sum lemma changes universes without recounting executable tables. Keep replacement-map coverage separate from values, with contains iff processed support and nonzero change; prove tombstones and unchanged keys explicitly. Saved ghost models of Arc contents need equality links in loop invariants, and executable borrows before ghost snapshots avoid moving out of Arc. Use assert forall ... antecedent implies conclusion by {...}, not a plain ==> inside a quantified assertion, when the proof body needs antecedent bounds. Join COUNT factorization must account for customer multiplicities and NULL extension; a named inner_weight(key,nonnull) spec function avoids distinct lambda identities when callers specialize nonnull to true/false. Hide nested SQL tuple definitions in downstream bridge lemmas to avoid recursive expansion. A recursive merge sort retaining the same O(D log D) algorithm permits local sorted-prefix and weighted-sum proofs.
